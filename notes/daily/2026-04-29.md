## Trabajo ejecutado

### Bug fix `modules/pages/listing_monitor.py`
- **Síntoma**: StreamlitAPIException en producción al abrir tab "Ver Alertas" cuando un ASIN traía bullets. Crasheaba con redacted error.
- **Causa real (diagnóstico via agente `code-reviewer`)**: `st.expander("Ver bullets actuales")` en L563 anidado dentro del expander padre por ASIN en L508. Streamlit no permite expanders anidados (`_check_nested_element_violation`).
- **Por qué era intermitente**: el bug solo explotaba en el branch `if data.get("bullets"):` (L562). ASINs sin bullets no entraban al if, por eso algunos scans pasaban.
- **Fix aplicado**: `st.expander("Ver bullets actuales")` → `st.popover("Ver bullets actuales")` (1 línea). Funcionalmente equivalente, no es block element, anida sin problema. streamlit==1.43.2 lo soporta.
- **Validación**: app live, screenshot confirmando módulo funcionando con ASIN B01M6DFC5W (Medix 5.5, marketplace MX) — KPIs visibles + botón popover funcional.

### Fix lateral `.claude/agents/code-reviewer.md`
- Model string deprecated (`claude-sonnet-4-5-20250514`) actualizado a `claude-sonnet-4-6`. Resolvía parcialmente el pendiente #9 del STATE-agencia.
- Síntoma del bug: el agente fallaba con `tool_uses=0` (no error claro). Después del update + re-invocación con model explícito, agente corrió clean (10 tool uses, 61k tokens, 1m17s).

## Decisiones tomadas

## Lecciones operativas (hard-earned)

### 1. Validar fix en disco + en HEAD antes de cerrar sesión
El sop-writer del cierre original reportó "fix aplicado" sin que el archivo se hubiera tocado en disco. Solo se cazó cuando un `git status` posterior no listó `listing_monitor.py` como modified al hacer `git add`. Regla nueva: después de cualquier supuesto fix de código, validar con DOS comandos antes del commit:
- `Select-String -Path <archivo> -Pattern <patrón> -Context 1` (estado del archivo en disco)
- `git show HEAD:<archivo> | Select-String -Pattern <patrón>` (estado en último commit)
Si los dos no concuerdan con lo esperado, el fix no está donde se cree.

### 2. Cruce de repos en Claude Code = riesgo real de pérdida de trabajo
Trabajando 2 proyectos en paralelo (ppc-manager + VendePro), un prompt operativo se mandó a la sesión equivocada de Claude Code. Resultado: un commit grande (28 files, 839+ insertions) se aplicó en VendePro `feat/sync-system` por error. Recuperación: branch revertida con `git push origin --delete <branch>` (no había mergeado, daño cero). Regla nueva: todo prompt operativo a Claude Code arranca con guarda obligatoria:
1. `pwd` (verificar carpeta)
2. `git remote -v` (verificar repo)
3. `git branch --show-current` (verificar branch)
Si cualquiera falla, parar.

### 3. Streamlit `st.popover` confirmado funcional en producción
El fix con `st.popover` en lugar de `st.expander` quedó live. UX: aparece como botón clickeable (visible en screenshot validación), abre popover con bullets. Comportamiento equivalente al expander pero sin la limitación de anidamiento. streamlit==1.43.2 lo soporta sin issue.

## Hallazgos / aprendizajes

- **Framework "Decomposición orgánico vs paid"** descubierto: cuando AM atribuye caída a PPC, primero descomponer total gap = ad gap + organic gap. Si organic gap > 50% → no es PPC, es operativo (OOS, listing, rank). Reusable para cualquier cuenta.
- **Campaign Analyzer puede mostrar zombies**: 8 campañas del plan 23/04 ya no existían en la cuenta. La fuente de verdad es siempre el BulkSheetExport, no el analyzer (gotcha #6 SOP del 28/04 confirmado por segunda vez).
- **STR real > Plan original 23/04** para negativos: el plan asumía contaminación que no existía. Senior level: aplicar optimizaciones solo cuando hay evidencia o ROI medible, no por "cobertura preventiva".
- **Best Seller badge → catalizador del récord**: el rank pasó de 24,672 → 6,261 (4× mejora) en pocos días, lo que disparó las ventas. El badge es resultado + acelerador (efecto bola de nieve).
