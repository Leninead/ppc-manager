## Frente 1 — Hotfix incidente Cloud (TemplateNotFound _placeholder.html)

Al hacer smoke en Cloud post-rediseño, propuesta fresh tiró `TemplateNotFound: '_placeholder.html'`. Discovery del CC confirmó: **NO era bug de código** (HEAD correcto, reproducción local imposible en 3 casos). Causa raíz: **deploy stale** — el proceso de Streamlit Cloud tenía el módulo `proposal_renderer` viejo cacheado en memoria (con el fallback `_PLACEHOLDER_TEMPLATE`) mientras el disco ya tenía el archivo borrado. ### Incidente 401 → causa raíz RLS
Al guardar primera propuesta: `401 Unauthorized`. Discovery del CC con curl directo:
- GET (lectura) → 200 OK
- POST (escritura) → PostgREST `42501: new row violates row-level security policy`
PostgREST traduce el rechazo RLS para rol anon a HTTP 401 (con `WWW-Authenticate: Bearer`), no a 403 — por eso parecía auth. Causa real: **RLS activado sin política de INSERT para anon**.

### Decisión: RLS deshabilitado (single-tenant)
Deshabilitado RLS en ambas tablas vía Edit table → uncheck "Enable RLS". Decisión consciente: app single-tenant interna, anon key con acceso full. **Deuda de seguridad registrada**: rotar a service_role key + RLS con políticas si en algún momento se abre a multi-tenant o se expone públicamente.

### Migración

## Aprendizajes operativos

### Lesson learned #3 (smoke pre-push insuficiente)
El smoke local con propuesta hidratada (`6861bbce__v45`) no cubrió el flujo de propuesta fresh sin blocks. El incidente Cloud (TemplateNotFound) se hubiera cazado con un smoke de propuesta fresh ANTES del push. **Nuevo protocolo**: antes de push que toque renderer/templates, smoke con (a) propuesta hidratada + (b) propuesta fresh creada desde wizard.

### Deploy stale en Streamlit Cloud
Push no garantiza re-import de módulos Python en Cloud — Streamlit re-corre el script pero el proceso mantiene módulos cacheados. Tras cambios estructurales en módulos core, **Reboot manual** de la app en Streamlit Cloud para forzar contenedor limpio.

### Supabase wiring — replicable
El swap day documentado en `notes/modules/m29-proposal-studio.md` funcionó casi al pie de la letra. Única sorpresa no documentada: RLS activado por default en tablas nuevas bloquea writes con anon. Agregar al playbook el paso "deshabilitar RLS (o crear políticas) post-DDL".
