## Lecciones de la sesion

1. **El analisis preliminar acelera al specialist**. Llegamos al
   data-persistence-specialist con 3 entidades + decisiones bloqueadas + cita
   exacta de las lineas del HTML donde vivia cada cosa. Resultado: 6/6 verde

   en mi prompt. Si el agente hubiera ejecutado literal, terminabamos con bug
   de UX (counts en 0), NameError en runtime, y violacion del skill. Documentado
   en commit message como leccion para futuras sesiones.

3. **Hot reload de Streamlit NO basta para cambios de layout**. Restart full
   del servidor (Ctrl+C + python -m streamlit run app.py) salvo varias veces
   en esta sesion. Heuristica: cambios de columnas, ifs condicionales, dialogs
   nuevos → restart, no F5.

4. **El modelo "_save_config client-agnostic vs config per-cliente" es comun
   en Account Health**. Va a aparecer otra vez en M29 Pricing Dashboard si
   tiene config per-cliente. Mantener Opcion A (modulo escribe directo con
   json) hasta M30+ con misma necesidad, ahi promover a `_save_client_config`.

5. **shutil.rmtree() en accion disparada por usuario es zona gris aceptable
   v1**. Documentado como Excepcion 2 en CLAUDE.md M28 con criterio de
   promocion. Mismo patron que Excepcion 1 (tracked-skus.json).

6. **2 commits separados (schema → modulo) en lugar de 1 monoblock fue
   red de seguridad gratis**. Si el porter del Bloque 3 fallaba, el schema
   del Bloque 2 quedaba aprovechable como base para retry.

7. **Layout responsivo con `st.columns()` requiere proporciones, no contenidos
   estaticos**. La regla del agente fue `[4, 1, 1]` siguiendo el HTML legacy,
   pero el texto "🗑️ Borrar cliente" no entra en peso 1. La regla mejor es:
   peso 1 SOLO para botones con icono solo o texto <= 8 caracteres; peso 2+
   cuando hay texto descriptivo.
