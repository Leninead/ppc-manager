# Daily 2026-04-26 — Variation Builder (M26)

## Objetivo
Crear feature nueva para generar flat file Amazon con 1 parent + N children agrupados (Pet Food, fptcustom).

## Lo que se hizo

### Análisis del template cliente
- Archivo: `PET_FOOD__1_.xlsm` (220 columnas, 10 hojas, 440 data validations, fptcustom version 2026.0426)
- Mapeo dinámico de `field_names` en runtime (no hardcoded por columna)
- Extracción de valores válidos desde hoja "Valores válidos" del template
- Round-trip test crítico: `.xlsm` con `keep_vba=True` → preserva macros, hojas y data validations ✅

- **Archivo**: `modules/pages/variation_builder.py` (929 líneas)
- **4 tabs**: Parent / Children + Theme / Preview / Descargar

- **Marketplaces v1**: solo MX (MXN), col 179 del template
- **Validaciones**: SKUs únicos, theme único por child, precio > 0, main_image_url obligatorio, mínimo 2 children
- **Test funcional end-to-end**: PASÓ (1 parent + 3 children generados correctamente, archivo abre limpio en Excel)

## Bugs fixeados hoy

**Bug 1 — Dropdown Sabor limitado a template**
- **Síntoma**: campo Sabor limitaba a valores del template Amazon. Cliente necesita valores custom (ej "Res")
- **Fix**: `SelectboxColumn` → `TextColumn` libre
- **Validación**: end-to-end OK, custom values persisten

## Bug abierto (pendiente próximo chat)

**`data_editor` en tab Children requiere doble entrada**
- **Síntoma**: al editar un valor en la tabla, la primera edición no persiste — hay que meter el valor 2 veces
- **Causa raíz**: `data_editor` sin key estable + input df que cambia de objeto en cada rerun
- **Fix diseñado**: patrón de 3 keys (`_vb_input_df` / `vb_data_editor` / `vb_children_df`)
- **Plan B si el fix de 3 keys falla**: envolver en `st.form` con submit explícito
- **NO aplicado aún** — requiere sesión de chat y testing adicional
