## M27 — sesión 2026-05-20

**Goal de la sesión:** B5-b — row extractor + initial Required validator. Helper `_extract_template_rows(wb, headers) -> tuple[list[dict], list[str]]` que extrae rows de data de la hoja Template como dicts sparse `{field_id: value}` + emite warnings por Required fields vacíos. Target: 80-120 LOC. Sin discovery previo necesario (B5-a + B2 + B4b cubren contexto).

**Trabajo realizado:**

### Fase 1 — Pre-flight + decisiones de diseño D1/D2/D3

- Pre-flight git status verde: working tree clean, main = origin/main, 5 commits M27 del 19/05 visibles + commits docs cierre.
- Checkpoint commit `fc31af8` antes de tocar el helper.
- 3 decisiones de diseño formuladas con recomendaciones:
  - **D1 — Filtrado rows internas Amazon**: opción A (defensivo en B5-b, no refactor del `_is_amazon_internal_row` legacy). Razón: no acoplar B5-b a refactor de código legacy validado.
  - **D2 — Representación celdas vacías**: sparse, todas las keys del field_id_row con vacías como `""`. Razón: coherencia con `_parse_data_definitions` que retorna todos los fields y B5-c necesita saber qué fields existen aunque estén vacíos.
  - **D3 — Criterio Required vacío**: requería discovery sobre archivos reales antes de cerrar.

### Fase 2 — Discovery D3 (ad-hoc, throwaway)

- Script `discovery_b5b_required.py` ejecutado contra 2 archivos reales identificados con `_detect_schema()`:
  - OLD/fptcustom = `ALRBB093_p_USA_2026__1_.xlsm` (Gamboa, marketplace USA, 164 fields)
  - NEW/ptd = `COAT__5_.xlsm` (template fresh, 225 fields, 0 data real)
- Hallazgos:
  - OLD valores únicos Required: `Optional` (114), `Required` (44), `Preferred` (6).
  - NEW valores únicos Required: `Optional` (123), `Conditionally Required` (78), `Recommended` (13), `Required` (11).
  - Mis keywords originales `{"yes", "required", "y", "true", "1"}` **inválidas** — data real usa `"Required"` capitalized exacto.
  - Q3 sobre rows del NEW reveló placeholders Amazon entre `field_id_row` y data real: row 6 = ejemplo (ABC123/SHIRT/(Default)), row 7 = banner emoji ✅, row 8 = otro placeholder (COAT solo).
- D3 cerrada: igualdad exacta `required.lower() == "required"`. "Conditionally Required" (78 fields PTD) NO triggera warning — lógica condicional excede scope B5-b initial validator.

### Fase 3 — Implementación B5-b

- Commit `dcfdc9d` sobre `modules/pages/flat_file_migrator.py` (+180 LOC).
- Helper `_extract_template_rows` insertado después de `_locate_template_headers`.
- 4 filtros iniciales (a-d) + filtro (e) agregado tras hallazgo Q3 del discovery (PTD placeholders).

- LOC final 149 (excede target 80-120 por docstring extenso ~48 LOC documentando D1/D2/D3 + edge cases). Decisión: mantener el docstring extenso — documenta razonamiento de decisiones para sesiones futuras.

### Fase 4 — Test E2E + fix D4

- Test ad-hoc `test_b5b_extract.py` con asserts contra 2 archivos reales.
- Primera corrida con `read_only=False`: hang >2min (openpyxl carga todas las data_validations del .xlsm). Workaround `read_only=True` funciona en <2s.
- Resultado primera corrida:
  - ✅ OLD: 7 rows, 149 warnings (cliente solo llenó ~10 Required críticas/SKU), item_sku='ALRBB093.P26', brand_name='Gamboa'.
  - ❌ NEW: 1 row leak — placeholder ABC123/SHIRT pasó los 4 filtros (no tiene `marketplace_id=`, no es ejemplo Amazon canónico con commas, no es banner emoji, no tiene cells vacías).
- D4 análisis: 5 opciones evaluadas. Cerré con opción combinada D4d (`"(Default)"` marker) + D4e (`_AMAZON_EXAMPLE_TYPES` check cols 1-5) con defense in depth.
- Fix D4d+D4e aplicado → **regresión catastrófica**: 7/7 OLD rows filtradas porque `_AMAZON_EXAMPLE_TYPES` contiene `"COAT"` y `'coat'.upper() == 'COAT'` matcheaba `feed_product_type='coat'` legítimo de Gamboa. CC detectó la regresión, paró sin commitear, reportó.
- Decisión revisada: opción B simple (solo señal `"(Default)"`). Justificación: `"(Default) Create or Replace"` es **valid value contractual** del dropdown Amazon para `::record_action` — no contenido de cliente. AND requiere ambas señales para filtrar, así que pierde más fácil que UNA señal robusta sola.
- Re-test post-fix: ✅ OLD=7, ✅ NEW=0, ✅ warnings consistentes. Commit `dcfdc9d`.

### Fase 5 — Audit code-reviewer + mitigaciones

- Sub-agente code-reviewer Opus 4.7 invocado post-commit sobre `dcfdc9d`. Patrón validado (3er hit operativo, mismo flujo que B5-a 19/05 y M28 09/05).
- Veredicto: APPROVE WITH CONCERNS · 0 bugs activos · 4 P1 + 4 P2 + 4 P3.
- Mitigaciones aplicadas en commit aparte `0f82d90` (+25 LOC):
  - **F1 (P1)** — Early-return con warning explícito si `field_ids` queda vacío post-parse. Previene fail-silent con headers corruptos.
  - **F5 (P2)** — Docstring extendido (sección Notes) clarificando conversión de tipos no-str (datetime/Decimal/int/float → `str(v)` raw, sin formateo). Contrato `dict[str, str]` preservado.
- 10 findings restantes documentados como deuda blanda (F2/F3/F4 P1, F6/F7/F8 P2, F9/F10/F11/F12 P3).

**Bloqueos encontrados:**

- 1 regresión catastrófica auto-detectada por CC durante el fix D4 inicial (ver Fase 4). Cerrada en la misma sesión con opción B simple. Lección consolidada: ANTES de combinar señales heurísticas, verificar que las constantes existentes (`_AMAZON_EXAMPLE_TYPES`) no colisionen con data legítima del dominio (categorías Amazon ≠ placeholders Amazon).
- 1 hang del openpyxl `read_only=False` con archivos .xlsm Amazon (~1.2MB). Workaround `read_only=True` adoptado en test. Documentado como deuda P2.

**Decisiones técnicas cerradas:**

- **D1 = A (defensivo en B5-b)**: 5 filtros consecutivos a-e dentro del helper, sin refactor del `_is_amazon_internal_row` legacy.
- **D2 = sparse**: dict resultante incluye todas las keys del field_id_row no vacías, con cells vacías como `""`.
- **D3 = `== "required"` exacta**: comparación de igualdad lowercased contra el string `"required"` literal. "Conditionally Required" explícitamente NO triggera.
- **D4 = opción B simple**: filtro placeholder PTD por `"(Default)"` substring en primeras 10 cols. No combinar con `_AMAZON_EXAMPLE_TYPES` por colisión con `feed_product_type` legítimo. Defense in depth descartado: 1 señal contractual estable > 2 señales con edge cases conocidos.
- **Workaround openpyxl**: `read_only=True` obligatorio para .xlsm Amazon > 1MB. Docstring del helper documenta el contrato.

**Tiempo invertido:** ~3h netas (pre-flight + discovery + impl + fix D4 + audit + mitigaciones).
