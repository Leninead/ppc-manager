## Trabajo del día

### Bloque B4 — Valid Values parser + Enum value translator

**B4a (9c85e06, +39 LOC)** — `_parse_valid_values(wb) -> dict[str, list[str]]` parsea la hoja "Valid Values" del workbook. Schema-agnostic (mismo formato wide en fptcustom y PTD). Strippea sufijo categoría `" - [ COAT ]"` / `" - [ coat ]"` / `" - [  ]"` con regex tolerante a corchetes vacíos. Constante `_VALID_VALUES_SUFFIX_RE`. 4/4 asserts verdes contra fptcustom (Update Delete + Brand Name) y PTD (Listing Action + Brand Name).

**B4b (c11faf0, +130 LOC)** — `_ENUM_VALUE_MAP` (3 enums críticos hardcoded) + `_build_value_map(old_vv, new_vv) -> tuple[dict, list[str]]` + `_DEPRECATED_OLD_ENUMS` frozenset.

Decisión de scope conservadora (A1+/B2/C1):
- **A1+**: cobertura de 3 enums con mapping 1:1 identidad o rewording confirmado (`Update Delete` ↔ `Listing Action`, `Parentage` ↔ `Parentage Level`, `Product ID Type` ↔ `Product Id Type`) + set `_DEPRECATED_OLD_ENUMS` con los 2 enums OLD sin contraparte PTD (`Relationship Type`, `Variation Theme`) para que B5 emita diagnósticos diferenciables.
- **B2**: `ISBN` → `None` (deprecated). Capybaras no maneja books, mapear ISBN→GTIN automático sería perpetuar errores de cliente.
- **C1**: `GCID` → `None` (deprecated). Lógica fallback row-level vive en B5, no en B4b.

`_build_value_map` valida que old_label/new_label/values declarados existan en valid values reales (de B4a), acumula warnings sin raisear. 4 asserts verdes + 0 warnings (las 2 templates de discovery son test cases limpios).

### Bloque B5-a — Header locator con D1+fallback

**B5-a (07e79fb, +191 LOC)** — `_locate_template_headers(wb)` identifica las rows estructurales de la hoja "Template" usando estrategia D1+fallback (auto-detección row-by-row + safety net hardcoded por schema).

Hallazgo crítico del discovery: asimetría OLD/NEW en headers.
- **fptcustom**: 3 rows header (row 1 settings, row 2 display, row 3 field_ids), data desde row 4.
- **PTD**: 5 rows header (row 1 settings base64, row 2 banner, row 3 group banners sparse, row 4 display, row 5 field_ids), data desde row 6.

Esa asimetría empírica justifica D1+fallback sobre D2 hardcoded puro: si Amazon cambia row count, auto-detección absorbe el cambio antes de caer al fallback.

Constante `_TEMPLATE_HEADER_FALLBACK` tabula los offsets conocidos. 2 helpers privados (`_looks_like_field_id`, `_looks_like_display_label`) detectan patterns:
- field_id: snake_case, bracketed `[marketplace_id=...]`, prefix `::`, hash indexing `#N.field`
- display: Title Case con espacios

Cross-validation con B2 (`_parse_data_definitions`): al menos 3/5 sample field_ids de la row detectada deben aparecer como keys en dd. Si falla, cae a fallback.

`detection_method` retornado como key del dict para que el caller sepa si auto o fallback se activó (señal de regresión potencial futura).

#### 4. Gotchas nuevas descubiertas

**Gotcha 14 — Pet Food MX 2026 endureció más**: `unit_count` y `unit_count_type` ahora son obligatorios. Tirar error 99001 si faltan. Para Flavor Boost 270g polvo: `unit_count=270`, `unit_count_type=gramo` (valores válidos: `unidad`, `gramo`, `metro`, `mililitro`, `metro cuadrado`).

**Gotcha 15 — PartialUpdate en variation child requiere flavor_name explícito**: aunque PartialUpdate "respeta los campos no enviados", Amazon valida la integridad del variation theme y exige `flavor_name` (o el atributo del theme) cuando se incluye `variation_theme=Sabor`. Sin flavor_name, tira error 99003 dos veces (uno por col 30 variation_theme, otro por col 41 flavor_name).

**Gotcha 16 — UPCs "nuevos" del fabricante pueden venir contaminados en GS1**: si el fabricante hace el update GS1 vinculándolos a ASINs viejos del mismo seller, Amazon dispara 8541. Pre-flight check sugerido: pedirle al fabricante NUNCA hacer update GS1 hasta que Amazon confirme creación del ASIN nuevo.

**Gotcha 17 — Campos vacíos en Update NO garantizan nulación**: si un SKU tuvo un valor inválido en un upload previo (ej: URL placeholder TBD), mandar el campo vacío en upload posterior NO lo borra necesariamente. Amazon retiene el valor previo. Para limpiar, sobreescribir con valor válido.

#### 5. Template version actualizada

El `.xlsm` que Mario/Lenin descargó del Seller Central tiene `TemplateType=fptcustom`, `Version=2026.0508` (knowledge documentaba 2026.0427). 222 columnas en el processing summary (2 cols extras `::number_of_attributes_*` que Amazon agrega post-procesamiento — no van en upload).
