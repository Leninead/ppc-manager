### 2. Resolución pregunta arquitectónica de persistencia

Decisión bloqueada: **local-first con Parquet en `data/`**, single-user (Marcos), backup manual a Drive viernes. Migration path documentado: Parquet → SQLite cuando aparezca 2do usuario → Postgres cuando aparezca equipo 3+.

## Decisiones tomadas

- **Local-first con Parquet, no DB cloud**. Trigger de migración documentado.
- **Snapshots fijos para Sonnet y Haiku, alias estable para Opus**. Snapshot fijo previene la recurrencia del incidente 2026-04-26 (deprecación silenciosa).
- **Convención de modelos del repo formalizada**: Opus para lógica pura (5 agentes, 45%), Sonnet para implementación (4 agentes, 36%), Haiku para markdown (2 agentes, 18%).
- **Append al CLAUDE.md en lugar de editar tablas históricas**. Cero riesgo de romper historia.
- **Estructura de paths data/**: opción A (`<area>/<cliente>/<modulo>/`).
- **`.gitignore` por defecto para datos cliente**. Decisión consistente con migración futura.
- **Porter NO arregla bugs durante porting**. El bug 30 vs 37 días del Pricing Dashboard del compañero queda como deuda técnica heredada.
- **Persistence specialist NO construye módulos enteros**. División de labor clara.
